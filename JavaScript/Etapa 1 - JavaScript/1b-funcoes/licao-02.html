Seu palpite

Da última vez: o que a função dobro sem return mostra? Você disse b) só 8. É a c) 8, depois undefined.

  • a) 8 e 8: acha que o r guarda o que o console.log mostrou.
  • b) só 8: acha que o console.log(r) não mostra nada. Ele mostra o valor de r, mesmo quando é undefined.
  • c) 8, depois undefined: o console.log de dentro mostra 8, e a função não devolve nada.
  • d) undefined, depois 8: inverte a ordem das linhas.

A ideia

No seu licao-05.js da 1a, a mesma condição de validação aparece duas vezes. Se você mudar uma e esquecer a outra, o código quebra. Uma função resolve isso: você escreve o código uma vez, dá um nome a ele, e usa o nome quantas vezes quiser (MDN, "Funções", "Declarando uma função").

A função recebe dados pelos parâmetros, entre parênteses. O return devolve um valor para quem chamou e encerra a função. Sem return, ela devolve undefined. Declarar a função não roda nada. Só a chamada, com parênteses, roda o código (MDN, "Funções", "Chamando funções"). Sem parênteses, o nome é a própria função, guardada como um valor.

Exemplo resolvido

function rotulo(nome, prioridade) {
  return nome + " (P" + prioridade + ")"
}
const r = rotulo("Pagar conta", 3)
console.log(r)
PassoO que aconteceu
1a declaração cria a função rotulo; nada roda ainda
2rotulo("Pagar conta", 3) chama a função: nome recebe "Pagar conta" e prioridade recebe 3
3o return devolve "Pagar conta (P3)", e a função acaba
4o valor devolvido fica em r
5console.log(r) mostra Pagar conta (P3)

Q3. Um colega diz: "classificar(3) devolve "Normal", porque o último return é o que vale". O que está errado nisso?


function classificar(p) {
  if (p === 3) {
    return "Alta"
  }
  return "Normal"
}


se a função classificar for chamada ela vai retornar alta de tidi jeito


Certo para classificar(3): devolve "Alta". O motivo é que o return encerra a função, e o segundo return nem roda (MDN, return). Mas não "de todo jeito": classificar(1) não entra no if e devolve "Normal".
