Seu palpite

Da última vez: o que o código com dois total mostra? Você disse c) um erro. É a b) 0.

  • a) 5: acha que o let de dentro troca o total de fora.
  • b) 0: o let de dentro cria outro total, que só existe dentro das chaves.
  • c) um erro: acha que dois let com o mesmo nome nunca podem existir. Eles podem, se estão em blocos diferentes.
  • d) undefined: acha que o total de fora se perde.

A ideia

No seu licao-05.js, você criou o let op; fora do do { }. Isso não foi por acaso. Um let ou const só existe dentro do bloco onde foi criado, ou seja, entre as chaves { } mais próximas. Isso é o escopo da variável. Fora do bloco, o nome não existe, e usar o nome dá ReferenceError. Um bloco interno pode ver as variáveis de fora. Um let com o mesmo nome dentro do bloco cria uma variável nova, que esconde a de fora até a chave fechar. O var não respeita o bloco, e é mais um motivo para não usar var (MDN, "Gramática e tipos", escopo de variável).

Feito




Certo. Rodei o licao-06.js: mostra Tem tarefa urgente. Numa cópia, testei "Pagar conta" no início, no meio e no fim da lista, e funcionou em todos. Sem "Pagar conta" na lista, nada aparece.


Você evitou uma armadilha: urgente = t === "Pagar conta" em cada volta apagaria o true nas voltas seguintes. O seu if só muda o valor para true. Um detalhe: o let urgente começa como undefined. Funciona, porque undefined é falsy, mas let urgente = false deixa a intenção clara.







Você agora sabe onde uma variável existe: um let ou const vive só no bloco onde foi criado, e uma variável usada depois do bloco precisa ser criada fora dele.
